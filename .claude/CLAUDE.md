# TMD Plain Forecast (working name `tmd-plain-forecast`)

Thai web app that rewrites official TMD (Thai Meteorological Department) daily and 7-day forecasts as short plain-language Thai, per region. Course project (NLP + ML), free tiers only. This folder is the repo root. Master plan: `PLAN.md`. Progress: `ai/PROGRESS.md` (read it first in every session). Spec: `docs/spec/scope-and-pipeline.md`.

## Architecture (one level)
- Offline Python pipeline on the team laptop: prep -> sentence classifier (hand-written Naive Bayes vs k-NN) -> regex extraction -> template generation. Output is JSON.
- JSON is loaded into Neon Postgres with `npm run load:neon` (Node, ADR 0014). A Next.js (App Router) + TypeScript + Tailwind app on Vercel reads the DB directly. Pages: `/` (daily and 7-day, last 7 days, 7 regions) and `/demo` (upload a TMD forecast PDF).
- One Python function on Vercel (`api/`) runs the same pipeline package for `/demo`. `/api/*` belongs to Python only; never create `app/api/`.
- Folder skeleton and rules for adding folders: `docs/architecture.md`.

## Folder map (root)
- Root markdown holds only project-level documents: `README.md` (overview), `PLAN.md` (scope and plan), `THIRD_PARTY_NOTICES.md`. `AGENTS.md` stays at the root because `next dev` rewrites it there.
- Code, created in Phase 0 and later: `app/`, `components/`, `lib/`, `api/`, `src/`, `scripts/`, `models/`, `db/`, `tests/`, `public/`.
- `docs/` project docs (`spec/`, `decisions/` ADRs, `design/` incl. `DESIGN-expo.md`, `research/`, `results/`; index in `docs/README.md`).
- `ai/` everything about working with the AI assistant: `ai/README.md` (index, workflow, rules for sessions), `ai/PROGRESS.md` (progress log and handoff), `ai/plans/` (phase plans), `ai/archive/` (superseded drafts), `ai/research/` (R1-R4). Moved here on 2026-11-19, see ADR 0019.
- `data/raw/` hand-downloaded TMD files (gitignored, 112 files, large). `data/excluded-scripted/` old scripted downloads, excluded by decision; never use.
- `course/` lecture slides and study notes. Not part of the app; do not read unless the task needs it.
- `docs/design/DESIGN-expo.md` design standard (read-only). `.claude/` this file, rules and skills.

## Design standard
- `docs/design/DESIGN-expo.md` is the primary design standard: color, type scale, radius, spacing, components, breakpoints. It is read-only: never edit it. Use its tokens by name, never inline hex.
- Thai font is **Anuphan** (`next/font/google`, `thai` + `latin` subsets), replacing the standard's Inter. Where the standard's Latin-only values would hurt Thai text (negative tracking, uppercase, tight line-height) the project's adaptations are listed in `docs/spec/design-system.md`. Change those there or in an ADR, not in `docs/design/DESIGN-expo.md`.

## Conventions
- Identifiers, file names, commit messages: English ASCII. Code comments and docstrings: Thai, short, explain why not what, own line.
- Python: type hints, Ruff, pytest, `encoding="utf-8"` on every file open, `json.dumps(..., ensure_ascii=False)`.
- TypeScript: strict, pinned to 6.0.x (typescript-eslint does not accept 7). Named exports except Next.js convention files. kebab-case file names.
- Server Components by default; `'use client'` only on leaf components. Only the data-access layer (`lib/data/`) reads `process.env` and the DB.
- Pure functions for logic; I/O only at the edges. Reuse before writing: search `lib/` and `src/` first; extract a shared helper on the third repetition, not before.
- Hand-written components with Tailwind (no shadcn/ui). Do not add dependencies without asking.
- Rules that load automatically: `.claude/rules/frontend.md`, `.claude/rules/python.md`. Procedures: skills in `.claude/skills/`.

## Gotchas
- The project path contains Thai characters, spaces and `&` ("NLP & ML Mini-Project"): always quote paths. Confirmed in Phase 0.1: `npm run` with a `node_modules/.bin` shim fails (`'ML' is not recognized`), calling `node node_modules/...` works (see Commands). If another tool fails on the path, report it; do not move files yourself.
- This root also holds docs, course notes and data. Tailwind scans only `app/`, `components/`, `lib/` (`@import "tailwindcss" source(none)` + `@source` in `app/globals.css`, verified in 0.1). Keep non-app folders out of the Vercel Python bundle (`excludeFiles`).
- Vercel Hobby limits: request body 4.5 MB (check PDF size in the browser first), Python bundle 500 MB (use `excludeFiles`), 300 s max duration. Python on Vercel works (spike 0.3, `/api/summarize` 5.1): installed from `pyproject.toml` by uv, 48 MB bundle, region `sin1`. Above 4.5 MB Vercel answers with its own non-JSON 413.

## Workflow
1. Read `ai/PROGRESS.md` and the current plan in `ai/plans/`. Work on one phase only.
2. New phase: plan first (plan mode, or `/planning-phases` if the user asked for planning).
3. Implement, then run the `testing-and-verification` skill: run the real checks, quote their output, update `ai/PROGRESS.md`.
4. Run `/code-review`, fix findings, stop and report: what was done, real test results, what was skipped or uncertain.
5. Handoff (another Claude account or session may continue this work from the local files, without git): at the end of every phase or session, update the "จุดส่งต่อ (handoff)" section at the top of `ai/PROGRESS.md` (last commit, files changed but not committed, what is done, the exact next step, what waits on the user) and keep `PLAN.md`, `.claude/CLAUDE.md` Commands and `docs/` in line with what exists. When resuming, read that section first, then re-run the listed checks before building on someone else's work; report anything that does not match.
6. If a phase fails verification twice, stop and ask the user. Do not change the data contract (`docs/spec/data-contract.md`) or the folder skeleton silently: record an ADR in `docs/decisions/`.
