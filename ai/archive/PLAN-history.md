## 2. ไอเดีย

*(เขียนใหม่ 2026-11-16 ให้ตรงขอบเขต: พยากรณ์ประจำวัน + พยากรณ์ 7 วัน)*

### 2.1 ปัญหา
ประชาชนทั่วไปอยากรู้แค่ว่า **"ภาคที่ฉันอยู่ ช่วงนี้อากาศเป็นอย่างไร และต้องระวังอะไร"** แต่ข้อความพยากรณ์ของกรมอุตุนิยมวิทยา (TMD) เขียนครอบคลุมทั้งประเทศ ในแม่แบบเดียว ผู้อ่านต้องอ่านทั้งฉบับแล้วหาเองว่าส่วนไหนเกี่ยวกับตน

### 2.2 หลักฐานของปัญหา (ตรวจจากข้อความจริงของ TMD ไม่ใช่จากการสำรวจผู้อ่าน)
1. **ยาวและรวมทั้งประเทศ:** หน้า `/forecast/daily` มี "ลักษณะอากาศทั่วไป" 4 ย่อหน้า (~1,900 อักษร) แล้วตามด้วย 7 บล็อกภาค ข้อความทั้งฉบับ PDF ประมาณ 4,500 อักษร (รายวัน) และ 6,800 อักษร (7 วัน) (นับจากชั้นข้อความ PDF วันที่ 14 พ.ย. 2026)
2. **ต้องหาภาคตัวเองเอง:** 7 บล็อก (เหนือ / อีสาน / กลาง / ตะวันออก / ใต้ฝั่งตะวันออก / ใต้ฝั่งตะวันตก / กรุงเทพฯและปริมณฑล) ภาคใต้ฝั่งตะวันออกมีบล็อกย่อยแบ่งตามจังหวัด ("ตั้งแต่จังหวัดสุราษฎร์ธานีขึ้นมา / นครศรีธรรมราชลงไป")
3. **สาเหตุเชิงเทคนิคปนกับคำเตือนในย่อหน้าเดียวกัน:** เช่น ฉบับ 14 พ.ย. เล่ากลไก "บริเวณความกดอากาศสูงหรือมวลอากาศเย็น… มรสุมตะวันออกเฉียงเหนือกำลังปานกลางพัดปกคลุม…" ก่อนจะถึง "ขอให้ประชาชนในภาคใต้ระวังอันตรายจากฝนตกหนักและฝนที่ตกสะสม…"
4. **ตัวเลขที่ไม่บอกความหมาย:** "ฝนฟ้าคะนองร้อยละ 30 ของพื้นที่" เป็นสัดส่วนพื้นที่ ไม่ใช่ความน่าจะเป็น ผู้อ่านอาจเข้าใจผิด [inferred] เกณฑ์ฝน (เล็กน้อย 0.1-11.0 / ปานกลาง 11.1-35.0 / หนัก 35.1-110.0 / หนักมาก ≥110.1 มม.) อยู่ท้ายฉบับ 7 วันเท่านั้น ฉบับรายวันไม่มีเกณฑ์ฝน
5. **ฉบับ 7 วันแบ่งตามช่วงวัน:** ภาคเหนือ / อีสาน / กลาง มี 3 ช่วงวัน ("ในช่วงวันที่ a - b … ส่วนในช่วงวันที่ … หลังจากนั้น …") ผู้อ่านต้องเรียงตามวันที่เอง
6. **คัดลอกจาก PDF ได้ข้อความเพี้ยน:** ชั้นข้อความ PDF รวมบล็อกภาคเป็นก้อนเดียวและแทรกช่องว่างกลางคำ ส่วนหน้า HTML (`/forecast/daily`, `/forecast/sevenday`) แยกบล็อกภาคสะอาด และถ้อยคำ/ตัวเลขตรงกับ PDF (เอเจนต์ B เทียบแล้ว) ดู [tmd-digest/B-forecast-and-downloads.md](../../docs/research/tmd-digest/B-forecast-and-downloads.md)

> **ยังไม่ได้พิสูจน์:** ว่าประชาชน "อ่านแล้วไม่เข้าใจ" จริง ยังไม่มีการสำรวจผู้อ่าน ข้อ 1-6 เป็นข้อเท็จจริงของข้อความ ส่วนผลต่อผู้อ่านเป็นการประเมินของทีม ตอน Q&A ให้ตอบตามนี้

### 2.3 ผู้ใช้
**ประชาชนทั่วไป** (ไม่เจาะกลุ่มเฉพาะ) อ่านภาษาไทยได้ ต้องการรู้สภาพอากาศของภาคตนแบบสั้นๆ โดยไม่ต้องเข้าใจศัพท์อุตุนิยมวิทยา เป้าหมายภาษา: ประโยคสั้น ไม่มีศัพท์เทคนิค ไม่มีตัวเลขที่ไม่อธิบาย คาดว่าเปิดจากมือถือ [inferred] จึงออกแบบหน้าให้อ่านง่ายบนจอเล็ก

### 2.4 สิ่งที่ทำ (วิธีแก้)
*(ปรับ 2026-11-16 รอบหลัง: เปลี่ยนจาก "ผู้ใช้วางข้อความเอง" เป็น "ไม่มีช่องกรอก")*

เว็บแอปที่ **ไม่มีช่องให้ผู้ใช้ใส่ข้อมูล** ผู้ใช้เปิดเว็บแล้วเห็นสรุปเลย: แสดง **ครบ 7 ภาคพร้อมกัน** มีแท็บ/ตัวเลือกโฟกัสภาคเดียว และเลือกวันย้อนหลังได้ (ย้อน 1 สัปดาห์) สรุปแต่ละภาคเป็นภาษาง่าย: สภาพอากาศ + ข้อแนะนำจากต้นฉบับ ตัดสาเหตุเชิงเทคนิคออก และอธิบายตัวเลขตามเกณฑ์ของ TMD

**ข้อมูลเข้า = ชุดข้อมูลที่ทีมเตรียมไว้ที่หลังบ้าน** (พยากรณ์ที่ TMD เผยแพร่ ทั้ง PDF และข้อมูลอื่นจากเว็บ) อัลกอริทึม (ขั้น 0-3) **รันที่เครื่องทีมจนเสร็จก่อนเผยแพร่** ผลสรุปออกเป็นไฟล์ JSON แล้วโหลดเข้าฐานข้อมูลฟรี หน้าเว็บอ่านจากฐานข้อมูลนั้น **อัปเดตวันถัดไปที่หลังบ้าน** = วางไฟล์พยากรณ์ใหม่ -> รันสคริปต์ -> โหลดเข้า DB -> เว็บอัปเดตตามโดยไม่ต้อง deploy ใหม่ ไม่มีการดึงจากเว็บ TMD อัตโนมัติ (ดูหัวข้อ 8)

โค้ดทั้งหมด (หน้าบ้าน + API ฝั่งเซิร์ฟเวอร์ + สคริปต์ประมวลผล + ข้อมูล + README) อยู่ใน **Git repo เดียว** (การสั่ง git ผู้ใช้เป็นคนสั่งเอง)

### 2.5 ทำไมต้อง NLP/ML
ข้อความเป็นภาษาไทยธรรมชาติที่ไม่ได้อยู่ในรูปข้อมูลโครงสร้าง ประโยค "สาเหตุ / สภาพอากาศ / คำเตือน" ปนอยู่ในย่อหน้าเดียวกัน ต้องแยกประเภทประโยค (ML จัดประเภทจากตัวอย่าง) แล้วเขียนใหม่เป็นภาษาง่าย (NLP) **ข้อสังเกตตามจริง:** เพราะข้อความ TMD เป็นแม่แบบตายตัว กฎ keyword ธรรมดาอาจแยกประเภทได้ดีพอกัน จึงใช้กฎเป็น baseline เทียบกับ Naive Bayes

### 2.6 ขอบเขต
- **ทำ:** พยากรณ์ประจำวัน + พยากรณ์ 7 วัน; ไม่มีช่องกรอก; แสดงสรุปครบ 7 ภาค + แท็บเลือกภาค; **ย้อนหลัง 1 สัปดาห์** (พยากรณ์รายวัน: ครบ 4 รอบต่อวัน เรียงล่าสุดก่อน เปิดดูย้อน 7 วัน; พยากรณ์ 7 วัน: 7 ฉบับ เรียงล่าสุดก่อน ตกลงแล้ว); ประมวลผลที่เครื่องทีมแล้วโหลดเข้า DB ฟรี; ฝึกโมเดลที่เครื่องทีมด้วยข้อมูลย้อนหลังที่เก็บได้ทั้งหมด (รายละเอียดท่อประมวลผลในหัวข้อ 3)
- **เพิ่ม (ผู้ใช้สั่ง 2026-11-16 รอบหลัง):** **หน้า Demo อัปโหลด PDF** อีก 1 หน้า ผู้ใช้อัปโหลด PDF พยากรณ์รายวัน/7 วัน แล้วระบบคำนวณอัลกอริทึมจริงและแสดงประโยคสรุป (ใช้สาธิตตอนพรีเซนต์) หน้าหลักยังเป็นแบบไม่มีช่องกรอก วิธีทำและข้อจำกัดดูหัวข้อ 6-7 ยังไม่ตัดสินวิธี
- **ไม่ทำ:** (ในหน้าหลัก) ช่องให้ผู้ใช้ใส่ข้อความเอง, ผู้ตรวจคนก่อนขึ้นเว็บ (ตัดสินใจ 2026-11-16 ไม่จำเป็น), ดึงอัตโนมัติ, ตารางตรวจวัดรายวัน (ตัวเลขล้วน ไม่มีข้อความ), พยากรณ์เดินเรือ, ตารางอุณหภูมิ 41 จังหวัด (มีเฉพาะ PDF ฉบับรายวัน), รายงานรายเดือน/ราย 3 เดือน/รายฤดู, คำเตือนภัยรายฉบับ

## 3. ท่อประมวลผล (ผลขั้น ML ส่งต่อขั้น NLP)

```
[หลังบ้าน บนเครื่องทีม]
ชุดข้อมูลพยากรณ์ (PDF/ข้อความ/API)
  -> [0 เตรียมข้อความ] -> [1 ML: จัดประเภทประโยค] -> [2 ดึงข้อมูลแยกตามภาค] -> [3 เขียนประโยคภาษาง่าย (NLP)]
  -> ผลสรุปรายภาค/รายฉบับ (ไฟล์ JSON) -> โหลดเข้า DB ฟรี
[หน้าบ้าน บน Vercel]
หน้าเว็บ (7 ภาคพร้อมกัน + แท็บ + เลือกวันย้อนหลัง 1 สัปดาห์) <- API ฝั่งเซิร์ฟเวอร์อ่านจาก DB
```

**ขอบเขตที่ตกลง (2026-11-16):** รับ 2 ประเภทเอกสารเท่านั้น คือ **พยากรณ์ประจำวัน (24 ชม.)** และ **พยากรณ์ 7 วัน** (ข้อความบรรยายโครงแม่แบบเดียวกัน ใช้ท่อเดียวกัน) ผลลัพธ์คือ **ประโยคสรุปภาษาง่ายรายภาค (ครบ 7 ภาค) ต่อเอกสาร 1 ฉบับ** แสดงบนเว็บ ไม่รับตารางตรวจวัดรายวัน (ตัวเลขล้วน ไม่มีข้อความ) พยากรณ์เดินเรือ ตาราง 41 จังหวัด หรือรายงานรายเดือน/ราย 3 เดือน/รายฤดู

| ขั้น | ทำอะไร | วิธีที่เรียน | วิชา / สไลด์อ้างอิง |
|---|---|---|---|
| 0 | **ตรวจชนิดเอกสารก่อน** (รับเฉพาะพยากรณ์รายวันและพยากรณ์ 7 วันของ TMD ไฟล์อื่นตอบข้อความเป็นมิตรว่ารองรับเฉพาะ 2 ชนิดนี้ ไม่คำนวณต่อ) แล้ว แก้ช่องว่างแทรกกลางคำจากการตัดบรรทัด (พบในทุก PDF) ตัดเป็นบล็อกภาค / ช่วงวัน / ประโยค ตัดคำไทย | กฎ + Word Segmentation (newmm) | NLP 1-2, 2-1 |
| 1 | ตัดสินว่าประโยคเป็น **สภาพอากาศ / ข้อแนะนำ-คำเตือน / สาเหตุเชิงเทคนิค / อื่นๆ** | **Naive Bayes** (หลัก) เทียบ **k-NN** · ฟีเจอร์ bag of words หรือ TF-IDF | ML 08 (text categorization, m-estimate), ML 04 · NLP 4-1 |
| 2 | แยกบล็อกตามภาค (ทำครบทั้ง 7 ภาค) ดึงค่า (ช่วงอุณหภูมิ ร้อยละพื้นที่ฝน ความสูงคลื่น ลม ชื่อจังหวัด) | regex / กฎ (ไม่ใช้โมเดล) | [general] ไม่ได้สอนตรงๆ |
| 3 | เขียนประโยคภาษาง่าย: ทิ้งประโยค "สาเหตุ" แทนศัพท์เทคนิคด้วยคำอธิบายของ TMD เอง (คลังศัพท์ใน `/info/*`) ใส่ความหมายให้ตัวเลขตามเกณฑ์ของ TMD เก็บประโยคแนะนำจากต้นฉบับ | แม่แบบ (template NLG) + พจนานุกรม | NLP 1-1 |
| Baseline (ขั้น 1) | กฎ keyword และ majority class | - | - |

**กฎของขั้น 3 (ห้ามละเมิด):** (1) ห้ามเปลี่ยน "ฝนร้อยละ N ของพื้นที่" เป็น "โอกาสฝนตก N%" เพราะหมายถึงสัดส่วนพื้นที่ ไม่ใช่ความน่าจะเป็น (2) ห้ามแต่งคำแนะนำที่ไม่มีในต้นฉบับ ใช้เฉพาะประโยคแนะนำที่ TMD เขียน (3) ตัวเลขทุกค่าต้องตรงต้นฉบับ (4) ใช้เกณฑ์ของ TMD เองเมื่ออธิบายระดับ (เช่น ฝนหนัก 35.1-110.0 มม. ตามหมายเหตุท้าย PDF 7 วัน)

**ตัวอย่างผลลัพธ์ (ข้อมูลจริง ภาคกลาง 16 พ.ย. 2026):** ต้นฉบับ "มีฝนฟ้าคะนองร้อยละ 30 ของพื้นที่ ส่วนมากบริเวณจังหวัดอุทัยธานี สระบุรี กาญจนบุรี ราชบุรี นครปฐม และสมุทรสาคร อุณหภูมิต่ำสุด 21-25 องศาเซลเซียส อุณหภูมิสูงสุด 34-36 องศาเซลเซียส" -> ผลลัพธ์ร่าง "ภาคกลางวันนี้: มีฝนฟ้าคะนองประมาณ 3 ใน 10 ของพื้นที่ภาค ส่วนมากที่อุทัยธานี สระบุรี กาญจนบุรี ราชบุรี นครปฐม และสมุทรสาคร อุณหภูมิต่ำสุด 21-25 และสูงสุด 34-36 องศาเซลเซียส"

**ข้อควรระวังเชิงวิธี:** ข้อความ TMD เป็นแม่แบบตายตัวมาก กฎ keyword ง่ายๆ อาจแยกประเภทประโยคได้ดีพอกับ Naive Bayes จึงใช้กฎเป็น baseline และรายงานผลตามจริง แม้ Naive Bayes ชนะนิดเดียวหรือแพ้ก็ใช้เป็นผลได้

- ข้อมูลที่ได้มาแล้วด้วยสคริปต์รอบสำรวจ (ใน `data-samples/`, `tmd-digest/`): ยังไม่ได้ตัดสินว่าจะเก็บไว้ใช้ภายในงานกลุ่มอย่างเดียวหรือตัดออกแล้วโหลดมือใหม่ ดูหัวข้อ 7

**ข้อค้นพบที่กระทบการออกแบบ (ดูรายละเอียดใน inventory):**
- รายงานระยะยาว (ราย 3 เดือน / รายฤดู) หน้า HTML เป็น iframe ไม่มีข้อความ เนื้อหามีใน PDF เท่านั้น; สรุปรายสัปดาห์มีข้อความใน HTML

**แผนเก็บข้อมูลที่เสนอ (2026-11-16 รอผู้ใช้ยืนยัน):** ข้อจำกัดคือรายวันย้อนได้แค่ 25 วัน และ 7 วันบนหน้าเว็บไม่มีย้อนหลัง
- **พยากรณ์รายวัน:** (ก) **ชุดแสดงบนเว็บ + ชุดทดสอบ = 7 วันล่าสุด ครบ 4 รอบ (28 ฉบับ)** (ข) **ชุดฝึก = 18 วันก่อนหน้า วันละ 1 รอบ (ราว 18 ฉบับ)** เพราะรอบในวันเดียวกันและวันติดกันคล้ายกัน 0.87-0.95 เก็บครบ 4 รอบไม่ช่วยเพิ่มความหลากหลายมากนัก คัดลอกข้อความจากหน้า HTML เก็บเป็น .txt (ข้อความแยกบล็อกภาคสะอาดแล้ว)
- **พยากรณ์ 7 วัน:** ฉบับล่าสุดคัดลอกจาก HTML; ฉบับย้อนหลังเปิด PDF `t_YYMMDD.pdf` ด้วยการพิมพ์ URL เอง **7 ฉบับสำหรับแสดงเว็บ/ทดสอบ + อีก ~10-15 ฉบับสำหรับฝึก** (PDF ข้อความแยกภาคยากกว่า ขั้น 0 ต้องรับมือ)
- **กติกาแบ่งตามวัน:** จาก 25 วัน: ฝึก 14 วันเก่าสุด, เว้น 1 วัน, dev 2 วัน, เว้น 1 วัน, ทดสอบ 7 วันล่าสุด (เว้นวันเพื่อลดข้อมูลรั่วระหว่างวันติดกัน) หลังวัดผลแล้วฝึกโมเดลสุดท้ายด้วยข้อมูลทั้งหมดที่ติดป้าย
- **ป้าย:** ติดป้ายเฉพาะส่วนที่สุ่มจากฉบับเหล่านี้ให้ได้ 300-500 หน่วย (ไม่ต้องติดทั้งหมด) ตัวเลขหน่วยต่อฉบับยังไม่ได้นับ
- **ข้อจำกัดที่ต้องเขียนในรายงาน:** ข้อมูลครอบคลุมแค่ปลายตุลาคม-กลางพฤศจิกายน (ฤดูฝนปลายฤดู/ต้นหนาว) โมเดลไม่เคยเห็นถ้อยคำของฤดูร้อนหรือฤดูฝนเต็มที่ ผลวัดจึงใช้ได้กับช่วงนี้เท่านั้น
- **เรื่องวิธีโหลด (ผู้ใช้ตัดสินใจ 2026-11-16 รอบท้าย):** ผู้ใช้อนุญาตให้ผมคุมเบราว์เซอร์เปิดหน้า/คัดลอกข้อความ/กดดาวน์โหลด PDF เก็บเป็นชุดข้อมูลฝึก **ครั้งเดียว** ข้อสังเกต: ข้อ 3.3 ของ TMD ระบุว่าต้องได้รับอนุญาตจากกรม (การอนุญาตของผู้ใช้ไม่ใช่การอนุญาตของกรม) ผู้ใช้รับทราบและตัดสินใจแล้ว วิธีที่ใช้: เปิดทีละหน้าเว้นจังหวะ ไม่ยิงถี่ ถ้าเจอ 403/429/Cloudflare ให้หยุด ไม่หลบ เก็บรายการที่โหลดทั้งหมดใน manifest

**Dataset ฝึกโมเดล:** ไม่มีสำเร็จรูป (ThaiSum, TR-TPBS เป็นข่าวทั่วไป) ต้องเลือกประโยคจากข้อมูลข้างบนแล้วติดป้ายเอง ราว 300-500 ประโยค

## 6. ข้อจำกัด / ความเสี่ยง

- **ต้องติดป้ายข้อมูลเอง** 300-500 ประโยค ใช้แรงคนมาก (อาจเริ่มจากกฎติดป้ายอัตโนมัติ แล้วแก้มือ)
- **ข้อความแม่แบบตายตัว:** ML อาจไม่เด่นกว่ากฎ keyword ยอมรับและรายงานตามจริง
- **ผลลัพธ์ต้องแม่น:** เลือก/เรียบเรียงจากต้นฉบับ ไม่แต่งข้อมูล ไม่แต่งคำแนะนำ ตัวเลขตรงต้นฉบับ มีข้อความบนหน้าเว็บระบุว่าเป็นตัวช่วยสรุป ไม่ใช่ประกาศทางการ และให้เครดิต "กรมอุตุนิยมวิทยา" ทุกหน้าที่แสดงผล
- **ข้อความ PDF ภาษาไทยของ TMD เพี้ยน** (ดูหัวข้อ 4) ชั้นข้อความ PDF รวมบล็อกภาคเข้าด้วยกัน แยกภาคยาก; ข้อความจากหน้า HTML แยกบล็อกสะอาดกว่า แต่ย้อนหลังต้องคัดลอกทีละฉบับด้วยมือ ต้องกำหนดว่าจะใช้แหล่งไหนเป็นหลัก (ดูคำถามเปิดหัวข้อ 7)
- **ถ้อยคำผันแปรเล็กน้อยตามฉบับ:** ย่อหน้าเรื่องฝุ่นมีเฉพาะบางฉบับ ตัวคั่นช่วงตัวเลขปนกัน ("-" และ "–") ฉบับ 7 วันใช้ชื่อภาคเต็มใน HTML แต่ชื่อย่อใน PDF ต้องรองรับ
- **ขอบเขตภาคในภาพรวมเป็นคำกว้าง (พบตอนสุ่มตรวจชุดข้อมูล 2026-11-16):** ย่อหน้า "ลักษณะอากาศทั่วไป" ใช้คำอย่าง "ประเทศไทยตอนบน", "ภาคใต้", "ภาคเหนือตอนบน", "อ่าวไทยตอนล่าง" และมีคำแนะนำเฉพาะกลุ่ม (เช่น เกษตรกร ชาวเรือ) ต้องกำหนดตารางแมป (ประเทศไทยตอนบน = เหนือ/อีสาน/กลาง/ตะวันออก/กรุงเทพฯ) ก่อนเลือกข้อแนะนำให้แต่ละภาค; ชื่อบล็อกกรุงเทพฯ ไม่คงที่ ("กรุงเทพและปริมณฑล" ใน HTML ฉบับ 23 ต.ค. เทียบกับ "กรุงเทพมหานครและปริมณฑล" ที่เห็นในที่อื่น) และบางรอบเนื้อหาภาคต่างกัน (ลม "แปรปรวน", "คลื่นต่ำกว่า 1 เมตร", ยอดดอย)
