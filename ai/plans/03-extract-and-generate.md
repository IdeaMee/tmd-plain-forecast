# แผน 03: ขั้น 2-3 ดึงค่า เลือกคำแนะนำตามภาค เขียนประโยคภาษาง่าย และรันทั้งชุด

**เป้าหมาย:** จากบล็อกภาคและหน่วยที่จัดประเภทแล้ว ได้ไฟล์ JSON ตามสัญญาของทุกฉบับที่จะแสดงบนเว็บ (รายวัน 28 รอบ + 7 วัน 7 ฉบับ) ที่ผ่านการตรวจ F1-F7

**สเปก:** [../../docs/spec/scope-and-pipeline.md](../../docs/spec/scope-and-pipeline.md) หัวข้อ 3-4 · [../../docs/spec/region-scope-map.md](../../docs/spec/region-scope-map.md) · [../../docs/spec/data-contract.md](../../docs/spec/data-contract.md) · skill `python-pipeline` (Generation rules), `testing-and-verification` (F1-F7)

**ข้อจำกัดที่ใช้:** ตัวเลข ช่วงตัวเลข และชื่อจังหวัดทุกค่าต้องอยู่ในข้อความต้นฉบับของภาคนั้น · คำแนะนำคัดมาตรงๆ ห้ามเขียนเอง · ห้ามเปลี่ยน "ร้อยละ N ของพื้นที่" เป็นโอกาสฝน · ใช้เกณฑ์ของ TMD เท่านั้นเมื่ออธิบายระดับ · ไม่แน่ใจว่าคำเตือนเกี่ยวกับภาคไหน ให้แสดงกว้างไว้ก่อน

## Phase 3.1: ดึงค่าจากบล็อกภาค   [M]   [เจ้าของ: ผู้ช่วย]   (ทำคู่ขนานกับแผน 02 ได้)

Goal: แต่ละบล็อกภาคให้ `facts` ที่ตรวจย้อนกลับไปหาข้อความต้นฉบับได้

Inputs
- บล็อกภาคจาก 1.3, ตารางจังหวัด → ภาค (`region-scope-map.md` หัวข้อ 4)

Tasks
1. `src/tmd_plain/extract/facts.py`: regex สำหรับ ร้อยละพื้นที่ฝน, อุณหภูมิต่ำสุด/สูงสุด (ช่วง), ทิศและความเร็วลม, ความสูงคลื่น, หมอก, รายชื่อจังหวัด, ช่วงวัน (7 วัน); เก็บข้อความต้นฉบับของแต่ละค่า
2. `tests/golden/facts/` ค่าที่ตรวจด้วยตา 5 ฉบับ (รายวัน 3, 7 วัน 2)

Checks
- `python -m pytest tests/extract -q` ผ่าน
- รายงานความครอบคลุมบนฉบับที่แสดงบนเว็บทั้งหมด: บรรทัดในบล็อกภาคที่ได้ค่าอย่างน้อยหนึ่งค่า (%) และรายการบรรทัดที่ไม่ได้ค่า (ไม่ใช่ข้อผิดพลาด แต่ต้องดูด้วยตา)
- ค่าทุกค่าใน `facts` เป็นสตริงย่อยของบล็อกต้นฉบับ (ทดสอบอัตโนมัติ)

Out of scope: คำแนะนำ, แม่แบบ

## Phase 3.2: เลือกคำแนะนำให้แต่ละภาค (ตารางแมปภาค)   [M]   [เจ้าของ: ผู้ช่วย; ผู้ใช้ตัดสินเรื่องเปิด]

Goal: หน่วย `advice` จากย่อหน้าภาพรวม/ข้อควรระวังไปอยู่ที่ภาคที่ถูกต้องตามข้อ D1-D7 และวัดเทียบกับ `scope` ที่คนติด

Inputs
- โมเดลที่อนุมัติ (2.4), `final_label` และ `scope` (2.3), `region-scope-map.md`

Tasks
1. `src/tmd_plain/extract/scope.py`: คำบอกที่ตั้ง → คีย์ภาคตาม D1-D7 (รวม "บริเวณดังกล่าว" สืบทอดหน่วยก่อนหน้า, ไม่มีคำบอกที่ตั้ง = ข้อแนะนำทั่วไป 7 ภาค)
2. `tests/extract/test_scope.py`: ทุกแถวในตารางแมปเป็นกรณีทดสอบ
3. `docs/results/scope-map-check.md`: จำนวนที่กฎแมปตรงกับ `scope` ของคน (~71 หน่วย advice) และทุกแถวที่ไม่ตรงพร้อมคำอธิบาย

Checks
- `python -m pytest tests/extract -q` ผ่าน · ตัวเลขในรายงานตรงกับผลรันซ้ำ
- ไม่มี advice ใดหายไป (ทุกหน่วย advice ปรากฏในอย่างน้อยหนึ่งภาคหรือในข้อแนะนำทั่วไป)

Human steps: ผู้ใช้ตัดสินเรื่องที่ยังเปิดในตารางแมป (หัวข้อ 7 ของ `region-scope-map.md`): หน่วย `weather` ในย่อหน้าภาพรวม (เช่น "อนึ่ง ในช่วงวันที่ …") จะแสดงในภาคไหม ค่าเริ่มต้นที่แนะนำ: ไม่แสดงในเวอร์ชันแรก เพราะบล็อกภาคมีสภาพอากาศของภาคนั้นอยู่แล้ว

Out of scope: แม่แบบ

## Phase 3.3: แม่แบบ พจนานุกรม และเกณฑ์ของ TMD   [M]   [เจ้าของ: ผู้ช่วย]

Goal: `facts` + advice กลายเป็น `RegionSummary` ภาษาง่ายตามสัญญา โดยไม่มีตัวเลขหรือคำแนะนำที่ไม่มีที่มา

Inputs
- ผลของ 3.1-3.2, ตัวอย่างผลลัพธ์ในสเปกหัวข้อ 4, หมายเหตุเกณฑ์ท้ายฉบับของ TMD, Q3 ที่ตกลงแล้ว (คงตัวเลขต้นฉบับ + คำอธิบายที่คำนวณในวงเล็บ)

Tasks
1. `src/tmd_plain/generate/templates.py`: ประโยคต่อชนิด (`rain`, `temperature`, `wind`, `wave`, `fog`, `other`), รายวัน → `lines`, 7 วัน → `periods`
2. `src/tmd_plain/generate/glossary.py` + `src/tmd_plain/resources/glossary.toml`: คำอธิบายจากนิยามของ TMD เท่านั้น เกณฑ์ฝน/ความหนาวตามหมายเหตุของฉบับนั้น
3. `src/tmd_plain/generate/assemble.py`: ประกอบ `Issue` (7 ภาค + `general_advice`) ด้วยโมเดล Pydantic จาก 1.1
4. ค่าที่คำนวณ (Q3) เก็บสูตรใน `facts` และเขียน ADR การขยายกฎ F1 (ยอมรับเฉพาะตัวเลขที่คำนวณจากค่าใน `facts` ตามสูตรที่ประกาศ)
5. `tests/golden/issues/`: ผลเต็มของ 3 ฉบับ (รายวัน 2, 7 วัน 1) ที่ตรวจด้วยตา

Checks
- `python -m pytest tests/generate -q` ผ่าน (รวม golden)
- ไม่มีคำว่า "โอกาส" ตามด้วยตัวเลขและ % หรือ "ความน่าจะเป็น" ในผลใดๆ
- ทุก `AdviceItem.text` เป็นสตริงย่อยของต้นฉบับหลังปรับช่องว่าง

Human steps: none

Out of scope: รันทั้งชุด (3.4), เว็บ

## Phase 3.4: รันทั้งชุด ตรวจ F1-F7 และให้ผู้ใช้อ่านเทียบ   [M]   [เจ้าของ: ทั้งสอง]

Goal: ได้ JSON ของฉบับที่แสดงบนเว็บทั้งหมด พร้อมรายงานการตรวจความถูกต้องที่ผ่าน และผู้ใช้ยอมรับถ้อยคำ

Inputs
- ทุกขั้นก่อนหน้า, `data/raw/` บทบาท `display_test` (รายวัน 28 รอบ, 7 วัน 7 ฉบับ)

Tasks
1. `scripts/run_pipeline.py` → `data/processed/<doc_type>/<issue_id>.json` (รายวันใช้ข้อความ HTML เป็นหลัก, 7 วันใช้ PDF ยกเว้นฉบับที่มีข้อความ)
2. `scripts/check_fidelity.py` → `docs/results/fidelity-report.md`: F1-F7 ทุกฉบับทุกภาค (F6 รันสองครั้งเทียบไบต์, F7 ป้อนไฟล์ว่าง/ข้อความมั่ว/ไม่ใช่พยากรณ์)
3. แก้ข้อบกพร่องที่พบ (เพิ่มเทสต์ทุกครั้ง)

Checks
- `python scripts/run_pipeline.py` → 35 ไฟล์ ตรวจผ่านโมเดล `Issue` ทั้งหมด
- `python scripts/check_fidelity.py` → F1-F7 ผ่าน 100% (ข้อที่ไม่ผ่านต้องแก้ ไม่ใช่ยกเว้นเงียบๆ)
- `python -m pytest -q` ทั้งชุดผ่าน · `ruff check .` ผ่าน

Human steps: ผู้ใช้อ่านสรุปอย่างน้อย 3 ฉบับ (ครบ 7 ภาค รวมฉบับ 7 วัน 1 ฉบับ) เทียบกับต้นฉบับ แล้วอนุมัติหรือส่งรายการแก้

Out of scope: โหลดเข้า DB (4.1)
