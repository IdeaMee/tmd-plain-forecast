- **Review gate มาตรฐาน (ใช้กับแผน 00-10 เดิม):** session แยก (ไม่ใช่ session ที่เขียนโค้ด) รันเช็กของ phase ซ้ำเอง สุ่มดู 5 ระเบียนจริงเทียบต้นฉบับ หา TODO, ตัวเลขที่ไม่มีที่มา, ไฟล์นอกรายการของ phase, การเปลี่ยนสัญญาข้อมูลเงียบๆ ผู้ตรวจไม่แก้โค้ด รายงานผล pass / fail / unsure
- **Stop conditions มาตรฐาน:** ตรวจไม่ผ่านสองครั้ง, สัญญาข้อมูลไม่ชัดหรือต้องเปลี่ยน (เขียน ADR ก่อน), ข้อมูลขาด, ต้องเพิ่ม dependency ที่ยังไม่ได้รับอนุญาต, เครื่องมือรันไม่ได้เพราะ path → หยุดและถามผู้ใช้
- **คำสั่ง:** ใช้คำสั่งจริงจากหัวข้อ `Commands` ใน `.claude/CLAUDE.md` (เติมใน 0.1) คำสั่งในแผนเป็นรูปแบบที่ตั้งใจ ถ้าต่างจากของจริงให้ใช้ของจริงและแก้แผน
- **ผู้ใช้เซ็นปิด** ทุก phase ก่อนเริ่ม phase ถัดไป (ข้อความสั้นๆ)
- **git:** ไม่มีขั้น commit ในแผน ผู้ใช้สั่งเองเมื่อพร้อม (`git push all main` ส่งทั้ง 3 repo ตาม ADR 0011) คะแนน Teamwork นับ commit ของสมาชิก จึงควรให้สมาชิกแต่ละคน commit งานของตัวเอง
- **ขนาด:** S = ไม่ถึงครึ่ง session, M = หนึ่ง session, ไม่มี L (ถ้างานโตเกินให้แยก phase)
- งานที่เขียน "เจ้าของ: ผู้ใช้" ผู้ช่วยทำแทนไม่ได้ (บัญชี, deploy, git, ติดป้าย 20%, อนุมัติ)
