## Phase 7.1: ต้นแบบภาพ 2 แนวทาง   [M]   [เจ้าของ: ผู้ช่วย; ผู้ใช้เลือก]

Goal: ผู้ใช้เห็นหน้าตาใหม่ 2 แนวทางในเบราว์เซอร์และเลือกหนึ่งแนวทาง (หรือผสม) ก่อนแก้โค้ดเว็บ

Inputs
- โทเคนใน `app/globals.css`, `design-system.md` หัวข้อ 3-6, ภาพหน้าจอเว็บปัจจุบัน (`npm run e2e` ใส่ภาพใน `test-results/screens/`)

Tasks
1. `docs/design/prototypes/a.html`, `b.html`: HTML + CSS ล้วน (ไฟล์เดียวต่อแนวทาง ไม่ใช้ framework) ใช้ค่าจากโทเคนเดิม + ข้อเสนอโทเคนใหม่ ข้อมูลตัวอย่างคัดจาก `data/processed/` จริง
2. ทุกแนวทางมีหน้าจอ: หน้าแรก (การ์ด 7 ภาค + ชิปภาค + ตัวเลือกรอบเปิดอยู่), การ์ดประกาศเตือนภัย 1 ใบ (ข้อมูลสมมติที่ระบุว่าเป็นตัวอย่าง), 1 ขั้นของภาพขั้นตอน `/demo` (ชิปคำ), เมนูมือถือสถานะเปิด, ที่ 375 และ 1280 px
3. อนิเมชันตัวอย่างใน CSS (เปิดเมนู, ชิปเลือกภาค, การ์ดเข้า) และโหมด `prefers-reduced-motion`
4. `docs/design/prototypes/README.md`: ความต่างของสองแนวทาง โทเคนใหม่ที่เสนอ และค่าความต่างสีที่คำนวณ (สูตร WCAG แบบ `design-system.md` หัวข้อ 6)

Outputs
- ต้นแบบ 2 ไฟล์ + README + ภาพหน้าจอ 375/1280 ของแต่ละแนวทาง

Checks
- เปิดทั้งสองไฟล์ในเบราว์เซอร์ที่ 320 / 375 / 768 / 1280 px: ไม่มี scroll แนวนอน (วัด `scrollWidth`), วรรณยุกต์ไม่ถูกตัด
- ค่าความต่างสีของสีข้อความใหม่ทุกคู่ ≥ 4.5:1 (ตารางใน README)
- `docs/design/DESIGN-expo.md` ไม่ถูกแก้: sha256 ก่อนและหลัง phase เท่ากัน (`Get-FileHash docs/design/DESIGN-expo.md`)

Human steps
- ผู้ใช้เลือกแนวทาง (หรือบอกว่าจะผสมส่วนไหน) แล้วเซ็นปิด

Out of scope
- แก้โค้ดใน `app/`, `components/`, `lib/`

## Phase 7.2: โทเคนการเคลื่อนไหว + คอมโพเนนต์พื้นฐาน v2   [M]   [เจ้าของ: ผู้ช่วย]

Goal: โทเคนและคอมโพเนนต์ `components/ui/` เป็นดีไซน์ที่เลือก มีโทเคนการเคลื่อนไหวชุดเดียวที่ทุกหน้าใช้ร่วม

Inputs
- แนวทางที่ผู้ใช้เลือกใน 7.1

Tasks
1. `app/globals.css` (`@theme`): เพิ่มโทเคนระยะเวลาและความเร่ง (เช่น `--duration-fast/base/slow`, `--ease-standard/emphasized`) และโทเคนสี/เงาใหม่ที่เลือก กฎ `@media (prefers-reduced-motion: reduce)` ปิดอนิเมชันทั้งหมด
2. `docs/spec/design-system.md`: แถว D11+ (โทเคนการเคลื่อนไหว เพราะ docs/design/DESIGN-expo.md บรรทัด 524 ระบุว่า animation timings อยู่นอกขอบเขต, สี/บล็อกที่เปลี่ยน) + ตารางความต่างสีใหม่ · ADR ใหม่ (เลขถัดไปที่ว่าง เช่น `docs/decisions/0015-design-v2.md`) บันทึกแนวทาง ข และทิศทางที่ผู้ใช้เลือก
3. `components/ui/`: ปรับ Button, Card, Badge, Alert, Skeleton, TabLinks (ตัวชี้เลื่อนตามแท็บที่เลือก) และเพิ่มชิ้นพื้นฐานที่ต้องใช้ซ้ำ (เช่น Collapsible ที่เปิด-ปิดนุ่ม, Chip) โดยไม่เพิ่ม dependency
4. `lib/motion.ts` (ถ้าต้องมีค่าใช้ร่วมใน TypeScript) + Vitest

Checks
- `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` ผ่าน · `npm run e2e` ผ่าน (หน้าเดิมยังทำงาน)
- ไม่มี hex นอก `app/globals.css` (`grep -rnE "#[0-9a-fA-F]{3,8}\b" app components lib`) · ไม่มี `text-muted|semantic-error|semantic-success` เป็นสีข้อความ · ไม่มี `tracking-|uppercase|leading-(none|tight)`
- Playwright โหมด `reducedMotion: 'reduce'` 1 เทสต์: หน้าแรกไม่มี animation ที่ทำงาน (`document.getAnimations().length === 0` หลังโหลด)
- `package.json` ไม่มี dependency ใหม่ (หรือผู้ใช้อนุมัติไว้ในข้อความ)

Human steps
- none (ถ้าต้องเพิ่ม dependency ให้หยุดถามก่อน)

Out of scope
- เลย์เอาต์ระดับหน้า, เมนู (7.3)

## Phase 7.3: โครงเว็บ: Header, เมนูมือถือแผงเต็ม, เมนู 5 หมวด, ทรานสิชันหน้า   [M]   [เจ้าของ: ผู้ช่วย; ผู้ใช้รีวิว]

Goal: เมนูมือถือเปิดเป็นแผงกว้างเท่า Header เลื่อนลง-ปิดขึ้น, เมนูเดสก์ท็อปรองรับ 5 หมวด, เปลี่ยนหน้ามีทรานสิชัน

Inputs
- 7.2, `view-transitions.md` (อ่านก่อนเขียน: `<ViewTransition>` จาก `react`, `addTransitionType`)

Tasks
1. `components/layout/header.tsx` + `components/layout/mobile-menu.tsx` (`'use client'` ใบเดียว): ปุ่มแฮมเบอร์เกอร์แปลงเป็น X, แผงเต็มความกว้างใต้ Header เลื่อนลง/ขึ้น, ปิดเมื่อ Esc/แตะนอกแผง/เปลี่ยนหน้า, `aria-expanded` + `aria-controls`, ล็อกการเลื่อนพื้นหลัง, โฟกัสวนในแผงเมื่อเปิด, ลิงก์สูง ≥ 48 px จัดกลุ่มตามหมวด
2. เมนูเดสก์ท็อป (≥ 768 px): 5 หมวด (พยากรณ์ · เตือนภัย · สรุปสภาพอากาศ · เกษตร · คาดหมาย) + ลองอัปโหลด + ความรู้/โมเดล เปิดหมวดย่อยได้ด้วยคลิกและคีย์บอร์ด · **แสดงเฉพาะหน้าที่มีอยู่จริง** (`lib/nav.ts` เป็นรายการเดียว ใส่หน้าใหม่เมื่อหน้านั้นเสร็จ ห้ามมีลิงก์ 404)
3. `app/layout.tsx`: ทรานสิชันเปลี่ยนหน้าด้วย `<ViewTransition>` (เฟด/เลื่อนตามทิศ) ตามเอกสารที่ติดตั้ง · Footer ใหม่
4. `tests/e2e/shell.spec.ts`: เปิด/ปิดเมนูมือถือด้วยแตะ Esc และคีย์บอร์ด, ลิงก์ทุกตัวในเมนูตอบ 200, ไม่มี scroll แนวนอนที่ 320/375/768/1280

Checks
- `npm run e2e` ผ่าน (รวม shell.spec) · ภาพหน้าจอเมนูปิด/เปิด ที่ 375 และ 1280 · คำสั่งตรวจของ 7.2 ผ่าน
- เบราว์เซอร์ที่ไม่รองรับ View Transitions (ทดสอบด้วยการปิดคุณสมบัติหรือเทสต์ที่ mock) ยังเปลี่ยนหน้าได้ปกติ

Human steps
- ผู้ใช้ลองเมนูมือถือบนเครื่องจริงหลัง push (ผู้ใช้สั่ง push) แล้วเซ็นปิด

Out of scope
- เนื้อหาในหน้า `/` และ `/demo` (7.4)

## Phase 7.4: หน้า `/` และ `/demo` ในดีไซน์ใหม่ + อนิเมชันการโต้ตอบ   [M]   [เจ้าของ: ผู้ช่วย; ผู้ใช้รีวิว]

Goal: หน้าเดิมทั้งสองหน้าเป็นดีไซน์ใหม่ และการโต้ตอบหลักมีอนิเมชัน: เปลี่ยนชนิดพยากรณ์ เปลี่ยนภาค เปิดตัวเลือกรอบย้อนหลัง โหลดข้อมูล

Tasks
1. `components/features/*` + `app/_components/*`: การ์ดภาคแบบใหม่, การ์ด 7 ใบเข้าแบบเหลื่อมเวลา, เปลี่ยนภาคแล้วการ์ดเลื่อน/ขยายเข้าที่ (shared element ด้วย `<ViewTransition name>`), ตัวเลือกรอบเปิดนุ่มและชิปรอบไหลเข้า, skeleton เฟดเป็นเนื้อหา (Suspense reveal)
2. `/demo`: ฟอร์มอัปโหลดและสถานะ (กำลังประมวลผล ผิดพลาด ผลลัพธ์) ในดีไซน์ใหม่ (ภาพขั้นตอนอยู่ในแผน 10)
3. ไม่มีอนิเมชันกับค่าตัวเลข: ตัวเลขแสดงค่าสุดท้ายทันที เคลื่อนแค่ตำแหน่ง/ความโปร่งใส
4. อัปเดต `docs/spec/ui-spec.md` (หัวข้อ 1-4) ให้ตรงกับดีไซน์ใหม่

Checks
- `npm run e2e` ผ่าน (เทสต์เดิม 24 ข้อปรับ selector ได้ แต่พฤติกรรมเดิมต้องผ่านครบ) · `npm test`, typecheck, lint, build ผ่าน
- ภาพหน้าจอ 320/375/768/1280 ของ `/` และ `/demo` ทุกสถานะ ไล่ `ui-checklist.md` ครบทุกหัวข้อ
- โหมด reduced-motion: ไม่มี animation ทำงาน · grep กฎข้อ 7.2 ผ่าน
- `npm run smoke` หลังผู้ใช้ push: 16 passed

Human steps
- ผู้ใช้รีวิวหน้าเว็บ (บนเครื่องหรือหลัง push) แล้วเซ็นปิด

Out of scope
- หน้าใหม่ (แผน 08, 10, 11, 12)
