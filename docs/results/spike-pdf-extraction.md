## บล็อกเดียวที่ตัวเลขไม่ครบ ไม่ใช่ความผิดของตัวอ่าน
`daily_151120261800` ภาคตะวันออก: HTML เขียน "ร้อยละ **20** ของพื้นที่" แต่ PDF เขียน "ร้อยละ **30** ของพื้นที่" ตรวจด้วยภาพหน้า PDF ที่เรนเดอร์แล้วว่าใน PDF เป็น 30 จริง → **TMD เผยแพร่ HTML กับ PDF ของรอบเดียวกันไม่ตรงกันได้** ผลจริงของการดึงข้อความจึงถูก 322/322 บล็อก

ผลต่อแผน: หน้าหลักใช้ข้อความ HTML ของรายวันเป็นหลัก (ตามแผน 3.4) ส่วนหน้า `/demo` ใช้ PDF ผลสองทางอาจต่างกันได้ ต้องเขียนเป็นข้อจำกัดในรายงาน

## ข้อบกพร่องที่พบเพิ่ม (บันทึกลง `known-defects.md` แล้ว)
1. **ช่องว่างหาย** ระหว่างคำที่ขึ้นบรรทัดใหม่หรือติดตัวหนา: "ราชบุรีนครปฐม", "ลมตะวันออกเฉียงใต้ความเร็ว", "ร้อยละ 30ของ", "ในช่วงวันที่17" (ตัวอักษรและตัวเลขครบ แค่ช่องว่างหาย)
2. **ตารางอุณหภูมิรายจังหวัดของรายวันปนอยู่ในบล็อกภาค:** ชื่อจังหวัดทีละบรรทัด ตามด้วยตัวเลขอุณหภูมิต่ำสุดทั้งหมด แล้วสูงสุดทั้งหมด (จับคู่ตามลำดับ) ไม่มีใน HTML → Phase 1.3 ต้องแยกออก
3. **หัวข้อภาคของ PDF อยู่บรรทัดเดียวกับเนื้อหา** ("ภาคเหนือ มีฝนฟ้าคะนอง...") และบางภาคสองบรรทัด ("ภาคตะวันออก / รวมทั้งชายฝั่ง", "ภาคใต้ฝั่งตะวันออก / (ฝั่งอ่าวไทย)", "กรุงเทพมหานคร / และปริมณฑล"); ฉบับ 7 วันไม่มีคำว่า "ภาค" ("เหนือ", "กลาง", "ใต้ฝั่งตะวันออก")
4. ไม่พบอักษร PUA ในไฟล์ชุดนี้เลย (ตัวแปลง PUA ยังเก็บไว้เผื่อไฟล์อื่น)

## ข้อจำกัดของการทดสอบนี้
- ตัวแยกภาคในสคริปต์เป็นแบบง่าย (หาหัวข้อตามลำดับหลังเครื่องหมายเริ่มส่วนรายภาค) ใช้วัดผลเท่านั้น ตัวจริงทำใน 1.3
- ตัววัด "ตัวเลขครบ" ดูว่าตัวเลขทุกตัวใน HTML มีใน PDF (นับซ้ำ) ไม่ได้ตรวจลำดับ และตัวเลขเกินจากตารางจังหวัดไม่นับเป็นผิด
- ความเหมือนของข้อความเป็นข้อมูลประกอบ (ชื่อจังหวัดในตารางทำให้ค่าลดลง)
- ฉบับ 7 วันมีคู่ HTML แค่ฉบับเดียว อีก 18 ฉบับตรวจได้แค่ว่าพบหัวข้อและวลีช่วงวัน และสุ่มดูภาพ 1 ฉบับ (`sevenday_261105` ภาคเหนือ ตรงกับข้อความที่ดึงได้)
- pdfminer.six ได้ 0 เพราะข้อความสลับลำดับและวรรณยุกต์แยกบรรทัด ไม่ได้ลองปรับค่า layout ของมัน
