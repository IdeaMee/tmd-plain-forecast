# ระบบดีไซน์ของโปรเจกต์: วิธีใช้ DESIGN-expo.md (ใช้งานจริง: ผู้ใช้รีวิวหน้า `/styleguide` ใน 0.5 และหน้าเว็บจริงใน 4.3/5.2 แล้วเซ็นปิด รวมข้อ D2/D3)

**มาตรฐานหลักคือ [../../DESIGN-expo.md](../../DESIGN-expo.md)** ผู้ใช้เป็นคนใส่ไว้ที่ Root และสั่งให้ **อ่านอย่างเดียว ห้ามแก้** ไฟล์นี้ไม่ได้แทนที่มัน แต่บันทึกสิ่งที่ DESIGN-expo.md ไม่ได้พูดถึงหรือใช้กับภาษาไทยตรงๆ ไม่ได้ เรื่องการเลือกวิธี: [../decisions/0010-design-standard-and-font.md](../decisions/0010-design-standard-and-font.md)

## 1. หลักการ
1. ทุกค่า (สี ขนาดตัวอักษร รัศมีมุม ระยะห่าง คอมโพเนนต์ จุดเปลี่ยนจอ) **ตาม DESIGN-expo.md** ยกเว้นข้อที่ระบุในหัวข้อ 4 ซึ่งแต่ละข้อมีเหตุผลและวิธีย้อนกลับ
2. อ้างโทเคนด้วยชื่อ (`primary`, `ink`, `body`, `hairline-strong`, `rounded.md` ...) **ห้ามเขียนรหัสสี hex ในคอมโพเนนต์** ตรงกับข้อ Iteration Guide ของมาตรฐาน
3. ถ้าต้องเบี่ยงจากมาตรฐานเพิ่ม: เพิ่มแถวในตารางหัวข้อ 4 (หรือเขียน ADR) ห้ามไปแก้ DESIGN-expo.md
4. มาตรฐานนี้เป็นภาพลักษณ์เว็บการตลาดของ Expo (ภาษาอังกฤษ ฟอนต์ Inter) เราใช้เฉพาะส่วนที่เข้ากับแอปอ่านข้อมูล ส่วนที่เป็นของการตลาดไม่สร้าง (หัวข้อ 5)

## 2. ฟอนต์ **Anuphan** (ผู้ใช้เลือก)
ข้อเท็จจริงที่ตรวจแล้ว 2026-11-16: [github.com/cadsondemak/Anuphan](https://github.com/cadsondemak/Anuphan) เป็น IBM Plex เวอร์ชันไทยแบบไม่มีหัว (Loopless) ของ Cadson Demak ใบอนุญาต **OFL-1.1** (ตาม GitHub API) · มีบน Google Fonts เป็นฟอนต์ตัวแปรน้ำหนัก 100-700 ชุดอักษร `latin`, `latin-ext`, `thai`, `vietnamese` · มีในรายการ `next/font/google` ของ Next.js 16.4.6 (เช็กจากไฟล์ font-data ของแพ็กเกจ) · **ยังไม่ได้ลองเรนเดอร์จริง** (ตรวจในหัวข้อ 7)

- ใช้เป็นฟอนต์เดียวของทุกบทบาทตัวอักษร แทน Inter ในมาตรฐาน (น้ำหนักตามมาตรฐาน: 600 หัวข้อ/ชื่อ, 500 ปุ่ม/เมนู, 400 เนื้อหา)
- โหลดด้วย `next/font/google`: `Anuphan({ subsets: ['thai', 'latin'], variable: '--font-anuphan', display: 'swap' })` (ไม่ระบุ weight = ฟอนต์ตัวแปร) ใส่ที่ `app/layout.tsx` ตั้ง `<html lang="th">` แล้วให้ `--font-sans` ใน Tailwind ชี้ไปที่ `var(--font-anuphan)` ตามด้วย `system-ui, sans-serif`
- JetBrains Mono (ฟอนต์โค้ดของมาตรฐาน): **ไม่โหลด** เพราะแอปไม่มีพื้นผิวแสดงโค้ด ถ้ามีในอนาคตค่อยเพิ่ม
- ถ้า `next/font/google` ใช้ไม่ได้ตอน build ให้ใช้ `next/font/local` กับไฟล์จาก GitHub ของฟอนต์ (OFL ต้องแนบข้อความใบอนุญาต) ทดสอบใน Phase 0
- เครดิตฟอนต์และมาตรฐานดีไซน์: [../../THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)

## 3. โทเคน → Tailwind
ทั้งหมดอยู่ที่เดียว: บล็อก `@theme` ใน `app/globals.css` คัดจาก front matter ของ DESIGN-expo.md มาตรงๆ (ไฟล์ CSS สร้างด้วยมือ ไม่มีสคริปต์แปลง) ให้ชื่อโทเคนเหมือนมาตรฐาน คอมโพเนนต์ใช้ `bg-primary`, `text-ink`, `text-body`, `border-hairline-strong`, `bg-surface-strong` ฯลฯ

| กลุ่ม | การทำ | หมายเหตุ |
|---|---|---|
| สี | `--color-<token>` ทุกตัวใน `colors:` ของมาตรฐาน | ดูข้อจำกัดความต่างสีในหัวข้อ 6 |
| ระยะห่าง | ใช้สเกล 4px เดิมของ Tailwind: xxs=`1`, xs=`2`, sm=`3`, base=`4`, md=`5`, lg=`6`, xl=`8`, xxl=`12`, section=`24` | ตรงกับสเกลของมาตรฐานโดยไม่ต้องตั้งค่าเพิ่ม |
| รัศมีมุม | ตั้ง `--radius-xs/sm/md/lg/xl/xxl` ใหม่ให้ตรงชื่อมาตรฐาน (4/6/8/12/16/24px) | ชื่อ `md` ของ Tailwind (6px) ไม่ตรงกับ `md` ของมาตรฐาน (8px) จึงต้องตั้งใหม่ ไม่งั้นสับสน |
| จุดเปลี่ยนจอ | ใช้ค่าเริ่มต้นของ Tailwind: `sm` 640, `md` 768, `lg` 1024, `xl` 1280 | ตรงกับมาตรฐาน (640 / 1024 / 1280 และเมนู hamburger ต่ำกว่า 768) |
| เงา | `--shadow-card-hover: 0 4px 12px rgba(0,0,0,0.04)` | เงาชั้นเดียวของมาตรฐาน ใช้ตอนโฮเวอร์การ์ดเท่านั้น |
| ขนาดตัวอักษร | `--text-<token>` พร้อม `--text-<token>--line-height` ตามตารางหัวข้อ 3.1 | line-height ปรับสำหรับภาษาไทย (ข้อ D3) |

ไวยากรณ์ `@theme` ของ Tailwind 4 (รวมการล้างค่าเริ่มต้นด้วย `--radius-*: initial`) ต้องยืนยันกับเอกสารของเวอร์ชันที่ติดตั้งใน Phase 0

## 6. ความต่างสี (คำนวณเองด้วยสูตร WCAG 2.x เมื่อ 2026-11-16 ตรวจซ้ำได้)

## 7. ผลตรวจ Phase 0.5 (2026-11-16) และสิ่งที่ยังต้องตรวจ
ตรวจแล้วบนหน้า `/styleguide` ด้วยข้อความพยากรณ์จริง: Anuphan โหลดผ่าน `next/font/google` ได้ (computed font = Anuphan); ไม่มี scroll แนวนอนที่ 320 / 375 / 768 / 1280 px; หัวข้อ 32 / 48 / 64 px line-height 1.3 และเนื้อหา 16 px line-height 1.6 ไม่เห็นวรรณยุกต์ถูกตัด; ปุ่มสูง 44 px บนจอสัมผัส (`pointer-coarse`) และ 40 px บนเมาส์; การ์ด 1 / 2 / 3 คอลัมน์; กรอบเนื้อหา 1200 px; ไวยากรณ์ `@theme` (รวม `--color-*: initial`, `--radius-*: initial`, `--text-*--line-height`, `--text-*--font-weight`) และ `source(none)` + `@source` ใช้ได้กับ Tailwind 4.3.3 · ข้อสังเกต: เบราว์เซอร์ตัดบรรทัดไทยตามพจนานุกรมของตัวเอง เช่น "ฝนฟ้า | คะนอง" ในหัวข้อใหญ่บนมือถือ (ไม่ใช่ข้อบกพร่องของฟอนต์ ถ้าต้องการกันตัดให้ใช้ `<wbr>`/nowrap เฉพาะคำใน Phase 4.2) · ผู้ใช้ดูหน้า `/styleguide` และเซ็นปิด 0.5 (2026-11-16) จึงใช้ D2/D3 ตามตาราง · หน้า `/styleguide` ลบแล้วใน 6.1

รายการเดิม (ตรวจครบแล้ว: `next/font/google` ตอน build บน Vercel ผ่านตั้งแต่ deploy แรก 2026-11-16 (หน้า `/styleguide` บนเว็บจริงแสดง Anuphan) และชิปภาคใน 4.2):
