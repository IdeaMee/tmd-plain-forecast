# ขอบเขตและท่อประมวลผล (สเปกที่ตกลงแล้ว)

ที่มา: สรุปจากข้อตกลงในขั้น 1 (2026-11-16) ใช้เป็นสเปกหลักของการสร้าง ถ้าจะเปลี่ยน ให้เขียน ADR ใน `docs/decisions/`

## 1. ปัญหาและผู้ใช้
ประชาชนทั่วไปอยากรู้ว่า "ภาคที่ฉันอยู่ ช่วงนี้อากาศเป็นอย่างไร ต้องระวังอะไร" แต่ข้อความพยากรณ์ของกรมอุตุนิยมวิทยา (TMD) เขียนครอบคลุมทั้งประเทศในแม่แบบเดียว หลักฐาน (ตรวจจากข้อความจริง ไม่ใช่การสำรวจผู้อ่าน):
1. ยาวและรวมทั้งประเทศ: ย่อหน้าภาพรวม 4 ย่อหน้า (~1,900 อักษร) + 7 บล็อกภาค; ทั้งฉบับราว 4,500 อักษร (รายวัน) และ 6,800 อักษร (7 วัน)
2. ต้องหาภาคตัวเองเอง (7 บล็อก; ภาคใต้ฝั่งตะวันออกมีบล็อกย่อยตามจังหวัด)
3. สาเหตุเชิงเทคนิค (ความกดอากาศสูง มรสุม) ปนกับคำเตือนในย่อหน้าเดียวกัน
4. ตัวเลขไม่บอกความหมาย: "ฝนฟ้าคะนองร้อยละ 30 ของพื้นที่" คือสัดส่วนพื้นที่ ไม่ใช่ความน่าจะเป็น; เกณฑ์ฝนมีเฉพาะท้ายฉบับ 7 วัน
5. ฉบับ 7 วันแบ่งตามช่วงวัน ผู้อ่านต้องเรียงเอง
6. ข้อความจาก PDF แยกภาคยาก (ชั้นข้อความรวมบล็อก)

**ยังไม่ได้พิสูจน์** ว่าประชาชนอ่านแล้วไม่เข้าใจจริง (ไม่มีการสำรวจผู้อ่าน) ผู้ใช้เป้าหมายคือประชาชนทั่วไป ไม่เจาะกลุ่มย่อย คาดว่าใช้มือถือ [inferred]

## 2. ขอบเขต
**ทำ**
- เอกสาร 2 ชนิด: พยากรณ์รายวัน (24 ชม. ออก 4 รอบต่อวัน) และพยากรณ์ 7 วัน (ออกวันละ 1 ฉบับ)
- หน้าหลัก (ไม่มีช่องกรอก): สรุปภาษาง่ายครบ 7 ภาค ย้อนหลัง 1 สัปดาห์ รายวันครบ 4 รอบต่อวัน ล่าสุดก่อน, 7 วัน 7 ฉบับ ล่าสุดก่อน, แท็บเลือกภาค
- หน้า `/demo`: อัปโหลด PDF พยากรณ์รายวัน/7 วัน แล้วคำนวณจริง (ไม่เก็บไฟล์; ใช้สาธิตและให้เพื่อนลอง)
- ประมวลผลที่เครื่องทีม -> JSON -> Neon -> เว็บอ่าน; อัปเดตโดยไม่ deploy ใหม่
- ตรวจชนิดเอกสารเป็นด่านแรก: ไฟล์ผิดชนิดตอบข้อความเป็นมิตร

**ไม่ทำ**
- ช่องให้ผู้ใช้ใส่ข้อความเองในหน้าหลัก; ผู้ตรวจคนก่อนขึ้นเว็บ; ดึงข้อมูลอัตโนมัติ
- ตารางตรวจวัดรายวัน (ตัวเลขล้วน), พยากรณ์เดินเรือ, ตารางอุณหภูมิ 41 จังหวัด, รายงานรายเดือน/ราย 3 เดือน/รายฤดู, ประกาศเตือนภัยรายฉบับ
- เอกสารของหน่วยงานอื่น/ภาษาอื่น (เป็นข้อจำกัดและงานต่อยอดในรายงาน)

## 3. ท่อประมวลผล

| ขั้น | ทำอะไร | วิธี | หัวข้อที่เรียน |
|---|---|---|---|
| doctype | ตรวจชนิดเอกสาร (รับเฉพาะรายวัน/7 วัน; แยกพยากรณ์เดินเรือ) | กฎจากหัวเอกสาร | - |
| 0 | แก้ข้อความ แยกบล็อกภาค/ช่วงวัน ตัดเป็นหน่วย (อนุประโยค) ตัดคำไทย | กฎ + newmm | NLP 1-2, 2-1 |
| 1 | จัดประเภทหน่วยเป็น weather / advice / cause / other | Naive Bayes เทียบ k-NN และกฎ keyword (baseline); bag of words หรือ TF-IDF | ML 08, ML 04, NLP 4-1 |
| 2 | แยกข้อมูลตามภาค ดึงค่า (ร้อยละพื้นที่ฝน อุณหภูมิ ลม คลื่น จังหวัด ช่วงวัน) และเลือกคำแนะนำให้แต่ละภาค | regex + ตารางแมปภาค | (ไม่ได้สอนตรงๆ) |
| 3 | เขียนประโยคภาษาง่าย ตัดสาเหตุ อธิบายตัวเลขตามเกณฑ์ TMD เก็บคำแนะนำจากต้นฉบับ | แม่แบบ + พจนานุกรม | NLP 1-1 |

- บรรทัดในบล็อกภาค (อุณหภูมิ ลม คลื่น ฝน จังหวัด) เป็น `weather` ตามตำแหน่ง ไม่ต้องจัดประเภท โมเดลขั้น 1 ทำงานกับย่อหน้าภาพรวมและส่วนข้อควรระวัง
- ตัดออกจากแผนเดิม: TF-IDF + cosine เรียงประโยค, Transformer, BLEU/chrF/ROUGE/BERTScore
- รายละเอียดป้ายและกติกาตัดหน่วย: `labeling-guideline.md`; ตารางแมปภาค: `region-scope-map.md`

## 4. กฎของผลลัพธ์ (ห้ามละเมิด)
1. ตัวเลข ช่วงตัวเลข และชื่อจังหวัดทุกค่า ต้องอยู่ในข้อความต้นฉบับของภาคนั้น
2. ประโยคแนะนำคัดมาตรงๆ จากต้นฉบับ ห้ามเขียนเอง
3. ห้ามเปลี่ยน "ร้อยละ N ของพื้นที่" เป็น "โอกาสฝน N%"
4. ใช้เกณฑ์ของ TMD เองเมื่ออธิบายระดับ (เช่น ฝนหนัก 35.1-110.0 มม.; อากาศเย็น 16.0-22.9, หนาว 8.0-15.9, หนาวจัด ต่ำกว่า 8.0 °C ตามหมายเหตุท้ายฉบับ)
5. ถ้าไม่แน่ใจว่าคำแนะนำเกี่ยวกับภาคไหน ให้แสดงกว้างไว้ก่อน (ไม่ตัดคำเตือนทิ้ง)
6. ทุกหน้าที่แสดงสรุปต้องมีข้อความ "ตัวช่วยสรุป ไม่ใช่ประกาศทางการ ที่มา: กรมอุตุนิยมวิทยา"

**ตัวอย่าง (ภาคกลาง 16 พ.ย. 2026):** ต้นฉบับ "มีฝนฟ้าคะนองร้อยละ 30 ของพื้นที่ ส่วนมากบริเวณจังหวัดอุทัยธานี สระบุรี กาญจนบุรี ราชบุรี นครปฐม และสมุทรสาคร อุณหภูมิต่ำสุด 21-25 องศาเซลเซียส อุณหภูมิสูงสุด 34-36 องศาเซลเซียส" -> "ภาคกลางวันนี้: มีฝนฟ้าคะนองประมาณ 3 ใน 10 ของพื้นที่ภาค ส่วนมากที่อุทัยธานี สระบุรี กาญจนบุรี ราชบุรี นครปฐม และสมุทรสาคร อุณหภูมิต่ำสุด 21-25 และสูงสุด 34-36 องศาเซลเซียส"

## 5. ข้อมูล
- เก็บแล้ว 2026-11-16: 112 ไฟล์ (ดู `docs/data-sources.md`) อยู่ใน `data/raw/` ไม่ขึ้น repo
- แสดงบนเว็บ + ชุดทดสอบ: รายวัน 28 รอบ (10-16 พ.ย.), 7 วัน 7 ฉบับ (10-16 พ.ย.)
- ชุดฝึก: รายวัน 18 วัน วันละ 1 รอบหมุนเวียน (23 ต.ค.-9 พ.ย.), 7 วัน 12 ฉบับ (28 ต.ค.-9 พ.ย.; ฉบับ 31 ต.ค. ไม่มี)
- แบ่งตามวัน: ฝึก 14 วันเก่าสุด, เว้น 1 วัน, dev 2 วัน, เว้น 1 วัน, ทดสอบ 7 วันล่าสุด; หลังวัดผลแล้วฝึกโมเดลสุดท้ายด้วยข้อมูลที่ติดป้ายทั้งหมด
- ติดป้ายทุกหน่วยย่อหน้าภาพรวมที่ไม่ซ้ำ (จริง 292 หน่วย จากโค้ดใน Phase 1.4; เดิมนับหยาบ ~310) โดยผู้ช่วยติดทั้งหมด และเป็นป้ายสุดท้ายโดยไม่มีคนติดซ้ำ ([ADR 0012](../decisions/0012-agent-labels-without-human-review.md); เดิมวางแผนให้ผู้ใช้ติดซ้ำ 20% เกณฑ์ตรงกัน ≥ 0.8); รายงานต้องเขียนว่า "ติดโดยโมเดลภาษา ไม่ได้ผ่านคนตรวจ"

## 6. การวัดผล (ขั้นต่ำ ตามที่ผู้ใช้สั่ง)
- accuracy ของ Naive Bayes / k-NN / กฎ keyword เทียบกัน + ตัวอย่างประโยคที่จัดผิด 3-5 ประโยค
- ชุดทดสอบแบ่งตามวัน; หน่วยถ้อยคำเหมือนกันอยู่ชุดเดียวกัน; รายงาน 2 แบบ: ทุกหน่วย และเฉพาะหน่วยถ้อยคำใหม่ (ตัวอย่างหลังจะน้อย ต้องบอกจำนวน)
- ตรวจอัตโนมัติ F1-F7 (ตัวเลข จังหวัด คำแนะนำ ไม่มี "โอกาส…%" ไม่ปนภาค ผลซ้ำได้ อินพุตผิดไม่ crash)
- ไม่ทำ: P/R/F1 แยก, ROUGE/BLEU, แบบสอบถามผู้อ่าน (ข้อแลกเปลี่ยน: เกณฑ์ Results 5% ของวิชา NLP ระบุ train-test, metrics, baseline, error analysis แบบขั้นต่ำข้างบนครอบคลุมส่วนใหญ่)

## 7. ข้อจำกัดที่ต้องเขียนในรายงาน
- ผลวัดใช้ได้กับ TMD รายวัน/7 วัน ช่วง 23 ต.ค.-16 พ.ย. 2026 เท่านั้น (ปลายฤดูฝน/ต้นหนาว)
- ขั้น 0, 2, 3 ผูกกับรูปแบบของ TMD; ขั้น 1 อาจใช้กับข้อความอื่นได้บ้างแต่ยังไม่ทดสอบ
- ป้ายติดโดยโมเดลภาษา (Claude) ไม่ได้ผ่านคนตรวจ (แก้ 2026-11-17 ตาม [ADR 0012](../decisions/0012-agent-labels-without-human-review.md); เดิม: ตรวจโดยคน 20%)
- ไม่ได้สำรวจผู้อ่านจริง; ข้อความ PDF ไทยเพี้ยนได้ ผลจากหน้า /demo อาจแม่นน้อยกว่าผลจากข้อความที่ผ่านหลังบ้าน
- ข้อกำหนด TMD: นโยบายเว็บข้อ 3.3 (สคริปต์อัตโนมัติ), `robots.txt` มี `ai-train=no` (ผู้ใช้รับทราบแล้วว่าเป็นงานรายวิชา ไม่ใช้เชิงพาณิชย์)

## 8. สิ่งที่ยังเปิดอยู่
วันส่งจริง, ขนาดทีมและบทบาท, ข้อสันนิษฐาน D3/D4 ของตารางแมปภาค (กรุงเทพฯ ใน "ประเทศไทยตอนบน", ภูมิศาสตร์อ่าวไทยตอนบน/ล่าง), จังหวัดปริมณฑล 3 จังหวัดที่ไม่ปรากฏในข้อมูล · ปิดแล้ว (2026-11-16/17): แผนฟรีของ Neon (ตรวจในบัญชีจริง ดู `PROGRESS.md`), spike Python บน Vercel (ผ่าน, `docs/results/spike-vercel-python.md`), ชื่อแพ็กเกจ `tmd_plain` (Q1) และชื่อแอป `tmd-plain-forecast`
