## อนิเมชันตัวอย่าง (CSS, เคลื่อนแค่ `transform` + `opacity`)
- เมนูมือถือ: แผงอยู่หลังแถบ Header แล้วเลื่อนลง (`translateY(-100%)` → `0`) + พื้นมืดจางเข้า, ปิดแล้วเลื่อนขึ้น · ไอคอนแฮมเบอร์เกอร์หมุนเป็น X · ปิดด้วยปุ่มเดิม แตะพื้นมืด หรือ Esc · โฟกัสวนในแผง · ล็อกการเลื่อนพื้นหลัง
- เมนูเดสก์ท็อป: แผงหมวดย่อยจางเข้า + เลื่อนลง 6 px, ลูกศรหมุน
- ชิปเลือก (ภาค รอบ วัน): ย่อ-ขยายสั้นๆ (`scale(.94)` → 1) เครื่องหมายถูกจางเข้า
- การ์ด 7 ภาค: จางเข้า + เลื่อนขึ้น 12 px เหลื่อมเวลาตามลำดับ (`--i` × `--stagger`) มีปุ่ม "เล่นการ์ดเข้าอีกครั้ง"
- ตัวชี้แท็บ: เลื่อนด้วย `translateX(100%)`
- ตัวเลือกรอบ: เนื้อหาเลื่อนลงจางเข้า แถว/ช่องรอบไหลเข้าเหลื่อมเวลา
- ชิปคำ: ไหลเข้าทีละชิป แล้วเส้นขีดฆ่าของชิปที่ถูกทิ้งค่อยๆ ลาก (`scaleX`) มีปุ่ม "เล่นขั้นนี้อีกครั้ง"
- การ์ดโฮเวอร์: ยกขึ้น 2-3 px เงาจางเข้า (เงาอยู่ใน pseudo-element เปลี่ยนแค่ `opacity`)
- **ไม่มีอนิเมชันกับค่าตัวเลข** ตัวเลขแสดงค่าสุดท้ายทันที
- `@media (prefers-reduced-motion: reduce)`: ปิด `animation` และ `transition` ทั้งหมด (ตรวจแล้ว: `document.getAnimations().length` = 0 ทั้งตอนโหลดและหลังเปิดเมนู ทั้ง A และ B)

## การเข้าถึง (ตรวจแล้วด้วย Playwright บน Edge)
- `<html lang="th">`, ไม่บล็อกการซูม
- ไม่มี scroll แนวนอน: `scrollWidth` เท่ากับความกว้างจอทุกขนาด
  | ไฟล์ | 320 | 375 | 768 | 1280 |
  |---|---|---|---|---|
  | a.html | 320 | 375 | 768 | 1280 |
  | b.html | 320 | 375 | 768 | 1280 |
- ทุก `a`/`button`/`summary` ที่มองเห็นกว้างและสูงอย่างน้อย 44 px (สคริปต์นับได้ 0 รายการที่เล็กกว่า ทุกขนาดจอ) ลิงก์ในเมนูมือถือสูง 48-56 px
- วงโฟกัส 2 px `ink` ห่าง 2 px กับทุกส่วนที่กดได้
- ไม่พึ่งสีอย่างเดียว: ตัวที่เลือก = พื้นดำ + เครื่องหมายถูก + `aria-current`; แท็บ = ก้อนดำ (A) หรือเส้นใต้ + ตัวหนา (B) + `aria-pressed`; ชิปที่ทิ้ง = ขีดฆ่า + เส้นประ + ข้อความ "ทิ้ง: …"; ชิปตัวเลข = ข้อความ "→ `<num>`"; เตือนภัย = ถ้อยคำ + ไอคอน; มาตรวัดฝน (B) มีข้อความกำกับเสมอ
- Esc ปิดเมนูมือถือแล้วโฟกัสกลับที่ปุ่ม (ตรวจที่ 375 และ 768)

## สิ่งที่ยังไม่แน่ใจ / ให้ผู้ใช้ตัดสิน
1. **เมนูเดสก์ท็อปที่ 768-1023 px**: 7 รายการ (5 หมวด + ลองอัปโหลด + ความรู้/โมเดล) ไม่พอดีบรรทัดที่ 768 ต้นแบบจึงใช้ปุ่มเมนู (แผงเต็มความกว้าง) จนถึง 1023 px และแสดงเมนูแนวนอนตั้งแต่ 1024 px ขึ้นไป แผน 7.3 เขียนว่าเมนูเดสก์ท็อป ≥ 768 px ต้องตัดสินว่าจะเลื่อนจุดเปลี่ยนเป็น 1024 (เสนอ) หรือย่อรายการที่ 768
2. หน้าย่อยในเมนู (เดินเรือ, สรุปรายสัปดาห์, เกษตร 7 วัน, คาดหมาย 3 เดือน, ความรู้/โมเดล) ยังไม่มีจริง ต้นแบบแสดงเพื่อดูโครงเท่านั้น เว็บจริงแสดงเฉพาะหน้าที่มีแล้ว (`lib/nav.ts`)
3. มาตรวัดพื้นที่ฝน (B) แสดงค่า `rain_area_tenths_high` ถ้าวันไหนเป็นช่วง (เช่น ร้อยละ 20-30) ต้องตัดสินวิธีแสดงช่วงบนมาตรวัด (เช่น เติมถึงค่าต่ำ + ลายเส้นถึงค่าสูง)
4. ชิปคำในหน้าจอ ค จัดด้วยมือ (การทิ้งช่องว่าง และการแยก "กม." "ชม." อาจต่างจาก newmm จริง)
5. ข้อความ "ประกาศเตือนภัยลักษณะอากาศ" และเนื้อหาการ์ดเตือนภัยเป็นตัวอย่างสมมติ โครงจริงต้องรอดูตัวอย่างประกาศที่เก็บในแผน 9.1
