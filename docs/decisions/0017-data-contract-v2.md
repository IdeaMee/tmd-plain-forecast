# 0017 สัญญาข้อมูล v2: ชนิดเอกสารรอบ 1 + โหมดทั่วไปของ `/demo` + trace (แก้ขอบเขต ADR 0002)

Status: accepted (2026-11-18, ผู้ใช้อนุมัติในแชต "อนุมัติตามข้อเสนอ") · แก้ขอบเขตของ ADR 0002

Context: ADR 0002 จำกัดไว้ 2 ชนิด (พยากรณ์รายวัน, 7 วัน) รอบปรับปรุง v2 (`plans/10`-`12`) ตกลงกับผู้ใช้ 2026-11-18 ว่าจะเพิ่มพยากรณ์เดินเรือ ประกาศเตือนภัย สรุปรายสัปดาห์ (รอบ 1) และให้ `/demo` รับเอกสาร TMD อื่นแบบโหมดทั่วไป พร้อมภาพขั้นตอนของอัลกอริทึม ตัวอย่างจริงเก็บแล้วใน 9.1-9.2 (เดินเรือ 100, ประกาศเตือนภัย 155, สรุปรายสัปดาห์ 100, generic 7) โครงของแต่ละชนิดคงที่พอให้สัญญาเดียวรองรับ: พื้นที่ทะเล 4 พื้นที่ครบทุกฉบับ, หัวภาคของสรุปรายสัปดาห์ครบ 7 ภาคทุกฉบับ, ประกาศเตือนภัยมีหัวเรื่อง/ฉบับที่/เลขประกาศ/ช่วงที่มีผลทุกฉบับ (ไม่มีฟิลด์ระดับแยก)

Decision:
- สัญญาข้อมูล v2 ตาม `docs/spec/data-contract.md` หัวข้อ "สัญญาข้อมูล v2": เพิ่ม `ShippingIssue`, `WarningNotice`, `WeeklySummary` (เก็บใน DB), `GenericDocument` (เฉพาะ `/demo`), `Trace` และคำตอบ `/api/summarize` แบบ `{ ok, kind, document, trace? }`
- `Issue` ของรายวัน/7 วันไม่เปลี่ยน: ผล 35 ไฟล์เดิมต้องเท่าเดิมทุกไบต์
- ขอบเขตเอกสาร (แทนส่วน "รับ 2 ชนิด" ของ ADR 0002): ชนิดที่สรุปเต็ม = รายวัน, 7 วัน, เดินเรือ, ประกาศเตือนภัย, สรุปรายสัปดาห์ · เกษตร 7 วันและคาดหมาย 3 เดือนรอผลประตู 12.1 (ADR ภาคต่อ) · เอกสาร TMD อื่นใน `/demo` = โหมดทั่วไป (ไม่เขียนข้อความใหม่) · ไฟล์ที่ไม่ใช่ PDF ปฏิเสธ (`unsupported_document`) · PDF ไม่มีชั้นข้อความ ปฏิเสธ (`extract_failed`) · เอกสารที่ไม่เหมือน TMD แสดงพร้อมคำเตือน `not_tmd_like`
- กฎความถูกต้องเดิมใช้กับทุกชนิด: ตัวเลข/จังหวัดในข้อความแม่แบบมาจากต้นฉบับ (F1 + ADR 0013), คำแนะนำ หัวเรื่อง ชื่อพื้นที่ ช่องตาราง คัดคำต่อคำ, ไม่สร้างระดับหรือสเกลสีเอง
- DB: ใช้ตาราง `forecast_issue` เดิม ขยาย check constraint ของ `doc_type` ใน 11.1 (ผู้ใช้อนุมัติและรันเอง) ไม่ลบข้อมูล
- ข้อตัดสินใจ V4: (ก) ป้าย `cause`/`weather` คงบทบาทเดิมในผลสรุป (ใช้คัดคำแนะนำ) แสดงป้ายทั้ง 4 แบบใน trace และโหมดทั่วไปเท่านั้น ผลรายวัน/7 วันไม่เปลี่ยน (ข) trace ไม่เกิน 256 KB ต่อคำตอบ ทุกรายการไม่เกิน 50 ชิ้น ตัดแล้วใส่ `truncated: true`

Consequences: `contract.py`, JSON Schema และ Zod ฝั่งเว็บโตขึ้น (เทสต์สัญญาต่อชนิด) · รูปคำตอบ `/api/summarize` เปลี่ยน ต้องเปลี่ยน Python กับเว็บใน commit เดียว (10.2) · ข้อความภาษาไทยของ `unsupported_document` และ `extract_failed` เปลี่ยนตามความหมายใหม่ · `CLAUDE.md` บรรทัด "Only two document types are supported" ต้องแก้ให้ตรง ADR นี้ · ฟิลด์จากตัวจัดประเภทประกาศเตือนภัย (11.3) และโมเดลของเกษตร 7 วัน/คาดหมาย 3 เดือน (แผน 12) จะเพิ่มด้วย ADR ภาคต่อ
