# 0015 เก็บข้อมูลหมวดใหม่และย้อนหลังด้วยเบราว์เซอร์ที่ผู้ใช้อนุมัติ (แก้ ADR 0001)

Status: accepted (2026-11-18, ผู้ใช้อนุมัติในแชต "Approve ADR 0015") · แก้ ADR 0001 (ส่วน "รอบเดียว")

Context: รอบปรับปรุง v2 (`plans/09-data-collection.md`) ต้องการข้อมูลหมวดใหม่ (พยากรณ์เดินเรือ, ประกาศเตือนภัย, สรุปรายสัปดาห์, เกษตร 7 วัน, คาดหมาย 3 เดือน, เอกสารอื่นสำหรับโหมดทั่วไปของ `/demo`) และย้อนหลังที่ยาวกว่า 23 ต.ค.-16 พ.ย. 2026 ADR 0001 อนุญาตการคุมเบราว์เซอร์ "รอบเดียว" ผู้ใช้อนุมัติในแชต 2026-11-18 ว่า "ให้คุณคุม Claude in Chrome ดาวโหลดเก็บไว้ให้ครบได้ อนุมัติให้ทำได้เลย" และ "สามารถคุม Claude in chrome เพื่อดาวโหลดข้อมูล set ที่จะใช้ทั้งหมดเก็บไว้ในเครื่องได้ ทำได้หมดเลยอิสระ" นโยบายเว็บ TMD ข้อ 3.3 และ `robots.txt` ยังเหมือนเดิม

Decision:
- ผู้ช่วยเก็บข้อมูลได้หลายรอบ (9.1 ตัวอย่าง, 9.2 ทุกฉบับในรายการของหน้าเว็บ, 9.3 คลังย้อนหลังลึก) ผ่าน Claude in Chrome ใน Chrome ของผู้ใช้เท่านั้น: เปิดหน้าตามที่คนเปิด อ่านข้อความที่หน้าแสดง และกดดาวน์โหลด PDF ที่หน้าให้ ไม่มีสคริปต์บนเครื่องยิง HTTP ไป tmd.go.th ไม่ใช้ API ไม่ตั้งเวลา
- เว้นจังหวะอย่างน้อย 2-3 วินาทีต่อหน้า ทำชุดละไม่เกิน ~100 ไฟล์แล้วพัก · เจอ CAPTCHA, หน้าบล็อก, 403/429 ซ้ำ หรือหน้าขอเข้าสู่ระบบ ให้หยุดและรายงาน ห้ามหาทางเลี่ยง
- ทุกไฟล์มีแถวใน `data/raw/MANIFEST.csv` (ที่มา ขนาด sha256 บทบาท) ตรวจด้วย `scripts/check_raw.py` · ไฟล์ดิบยังไม่ขึ้น repo · ท่อประมวลผลยังอ่านไฟล์ในเครื่องเท่านั้น
- วิธีเก็บทีละหมวด: `docs/research/collection-procedure.md`

Consequences: ข้อมูลย้อนหลังและหมวดใหม่มากพอสำหรับแผน 10-12 · กฎ "never fetch tmd.go.th with scripts" ใน `CLAUDE.md` ยังอยู่ (สคริปต์ยังห้าม) โดยมีข้อยกเว้นการเก็บด้วยเบราว์เซอร์ตาม ADR นี้ · ยังต้องให้เครดิต "กรมอุตุนิยมวิทยา" ทุกหน้าที่แสดงผล · ถ้ากรมหรือเว็บแสดงว่าไม่ยอมรับการเข้าถึงลักษณะนี้ ให้หยุดและทบทวน ADR นี้
